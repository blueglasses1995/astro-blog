# Document Knowledge Skill

このスキルは、ユーザーが提供した情報を整理・要約し、適切なドキュメントファイルに格納するサブエージェントを実行します。

## 目的

人間が「どこに何を書くか」を考える負担を減らし、情報を提供するだけで適切な場所に自動的に格納されるようにします。

## 情報分類ルール

### ADR（Architecture Decision Record）
以下の情報はADRとして分類：
- アーキテクチャの選択理由
- 技術スタックの採用判断
- 設計パターンの選択
- フレームワーク・ライブラリの選定理由
- インフラ・デプロイメント戦略の決定

**形式（50行以下厳守）:**
```markdown
---
title: "[タイトル]"
category: "adr"
type: "adr"
version: "1.0.0"
last_updated: "[YYYY-MM-DD]"
immutable: true
tags: ["tag1", "tag2"]
---

# ADR-XXXX: [タイトル]

## 決定
[採用したアーキテクチャ・技術を簡潔に]

## ルール
[具体的なルールを箇条書き]

## 理由
[なぜこの決定をしたのか、箇条書きで簡潔に]

## トレードオフ
**利点**: [利点]
**制限**: [制限事項]

## 参考
[参考リンク（あれば）]
```

### ドメイン知識
- **用語集**: プロジェクト固有の概念・用語の定義
- **不変条件**: ビジネスルール・データ整合性の制約
- **ビジネスルール**: 業務ロジック・例外処理のルール
- **エラーハンドリング**: エラー発生時の処理方針

### セキュリティ
- **セキュリティポリシー**: 認証・認可・データ保護の方針
- **プライバシー**: 個人情報保護・GDPR対応
- **監査**: ログ・監査要件・コンプライアンス

### 運用
- **パフォーマンス**: SLA・レスポンス時間・スループット要件
- **デプロイメント**: 環境構築・デプロイ手順・ロールバック戦略
- **バックアップ**: データバックアップ・災害復旧計画
- **トラブルシューティング**: 過去の障害・解決方法の記録

### 開発
- **コード生成ルール**: AIがコードを生成する際のルール
- **テスト戦略**: テスト方針・カバレッジ要件・テスト種類
- **コードレビュー**: レビュー基準・チェックリスト
- **リリース**: リリースプロセス・バージョニング
- **Git**: ブランチ戦略・コミット規約・ワークフロー

### 統合
- **外部依存関係**: サードパーティライブラリの管理方針
- **API統合**: 外部APIの統合制約・レート制限・エラーハンドリング
- **データマイグレーション**: スキーマ変更・データ移行の方針

## 処理フロー

1. **情報の受領**: ユーザーから情報を受け取る
2. **分類**: 情報の種類を判断（ADR、ドメイン知識、セキュリティなど）
3. **要約**: 情報を簡潔に整理（ADRは50行以下、その他は100行以下）
4. **ファイル選択**: 適切なディレクトリ・ファイルを選択
5. **既存内容の確認**: 既存ファイルがある場合は内容を確認
6. **統合**: 既存内容と統合（重複を避け、追加・更新）
7. **ファイル作成・更新**: 適切な形式でファイルを作成・更新
8. **シンボリックリンク**: `.serena/memories/`にシンボリックリンクを作成（存在する場合）

## 書き方のガイドライン

### 簡潔性
- **ADRは50行以下**に保つ（厳守）
- その他のファイルは100行以下
- 詳細は別ファイルに分割するか、`@docs/`で参照
- 冗長な説明は徹底的に排除

### 構造化
- 見出しを使って構造化
- 箇条書きを活用
- 表形式で比較情報を整理

### 具体性
- 抽象的な説明より具体例を優先
- コード例・設定例を含める
- 実装方法を明記

### 更新可能性
- ミュータブルファイルは「最終更新日」を記録
- 変更履歴を簡潔に記録（必要に応じて）
- 古い情報は削除またはアーカイブ

## 注意事項

- ADRは一度作成したら変更しない（新しい決定は新しいファイル）
- **ADRは50行以下を厳守**（Git hooksでチェック）
- その他のファイルは100行以下
- 既存のADRファイルを編集する場合は、ユーザーに確認を求める
- `.serena/memories/`が存在する場合は、シンボリックリンクを作成
- 重複情報は統合し、一箇所に集約

## サブエージェントの実行手順

1. **情報の受領と分析**
   - ユーザーから提供された情報を読み取る
   - 情報の種類を判断（ADR、ドメイン知識、セキュリティなど）
   - 既存のドキュメント構造を確認

2. **分類の決定**
   - 上記の分類基準に基づいて適切なカテゴリを選択
   - 複数のカテゴリに該当する場合は、最も適切なものを選択
   - 不明な場合は、ユーザーに確認

3. **ファイルの選択**
   - 選択したカテゴリに応じて適切なファイルを選択
   - 既存ファイルがある場合は内容を確認
   - 新しいファイルが必要な場合は、適切な名前を決定

4. **内容の要約と整理**
   - 提供された情報を簡潔に要約（100行以下を目安）
   - 既存内容と重複がないか確認
   - 構造化された形式に整理（見出し、箇条書き、表など）

5. **ファイルの作成・更新**
   - ADRの場合は、既存のADR番号を確認してから新しい番号を割り当て
   - ミュータブルファイルの場合は、既存内容に統合または更新
   - 適切なMarkdown形式で記述

6. **シンボリックリンクの作成**
   - `.serena/memories/`ディレクトリが存在する場合
   - 作成・更新したファイルへのシンボリックリンクを作成
   - リンク名は適切に決定（例: `ubiquitous_language.md` → `ubiquitous_language.md`）

7. **メタデータの追加**
   - フロントマター（YAML）を自動的に追加
   - タイトル、カテゴリ、タイプ、バージョン、最終更新日を記録
   - 関連ドキュメントへのリンクを追加
   - タグを自動付与

8. **シンボリックリンクの作成**
   - `.serena/memories/`が存在する場合、シンボリックリンクを作成
   - リンク名は適切に決定

9. **インデックスの自動更新**
   - `docs/README.md`（ドキュメントインデックス）を自動更新
   - `npm run docs:index`を実行してインデックスを生成

10. **結果の報告**
    - 作成・更新したファイルのパスを報告
    - シンボリックリンクの作成状況を報告
    - インデックスの更新状況を報告
    - 必要に応じて、追加情報を求める

## メタデータの自動追加

すべてのドキュメントファイルにフロントマター（YAML）を自動的に追加します。

### フロントマターの形式

```yaml
---
title: "[ドキュメントタイトル]"
category: "[カテゴリ: domain|security|operations|development|integration|adr]"
type: "[タイプ: glossary|invariants|policy|process|strategy|adr]"
version: "1.0.0"
last_updated: "[YYYY-MM-DD形式の日付]"
related_docs:
  - "[関連ドキュメントのパス]"
immutable: [true|false]
tags:
  - "[タグ1]"
  - "[タグ2]"
---
```

### メタデータの自動決定ルール

- **title**: ドキュメントの最初の見出しから抽出、またはファイル名から生成
- **category**: ディレクトリ構造から自動決定（`docs/domain/` → `domain`）
- **type**: ファイル名と内容から判断
  - `ubiquitous_language.md` → `glossary`
  - `domain_invariants.md` → `invariants`
  - `*_policy.md` → `policy`
  - `*_process.md` → `process`
  - `*_strategy.md` → `strategy`
  - `adr/*.md` → `adr`
- **version**: 新規作成時は`1.0.0`、更新時はマイナーバージョンを上げる
- **last_updated**: 現在の日付を自動設定
- **related_docs**: 内容から関連ドキュメントを推測して追加
- **immutable**: ADRは`true`、その他は`false`
- **tags**: 内容から自動的にタグを付与

## インデックスの自動更新

ドキュメントを作成・更新した後、`docs/README.md`（ドキュメントインデックス）を自動更新します。

**実行方法:**
```bash
npm run docs:index
```

**生成される内容:**
- カテゴリごとのドキュメント一覧
- ADR一覧
- タグ一覧
- 各ドキュメントのメタ情報（バージョン、最終更新日、関連ドキュメント）

## 実装時の注意点

- ユーザーが提供した情報が不十分な場合は、追加情報を求める
- 既存のドキュメントと矛盾する場合は、ユーザーに確認する
- ファイルが100行を超える場合は、分割を検討するかユーザーに確認
- ADRファイルを編集する場合は、必ずユーザーに確認を求める
- シンボリックリンクの作成に失敗した場合は、警告を出すが処理は続行
- メタデータの追加に失敗した場合は、警告を出すが処理は続行
- インデックスの更新に失敗した場合は、警告を出すが処理は続行
